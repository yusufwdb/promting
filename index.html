Module 01 · ~10 min read

Introduction to Prompt Engineering

Big Idea: A language model produces a continuation of the information it receives. Prompt engineering is the practice of making that continuation useful, relevant, and reliable.

🖥 Interactive Presentation Slides · Module 1
Slide 1 of 4 · Core Concept
The Central Question of Prompting

What makes a model's next words useful for a particular task? When given an opening prompt, thousands of continuations are plausible.

  • Instructions: Explicitly describe the task, audience, and constraints.
  • Context: Provide verified facts, references, and conversation state.
  • Output Schema: Dictate exact structure (JSON, table, bulleted steps).
Slide 2 of 4 · Architecture Evolution
From Markov to the Transformer

The progression of sequence modeling:

  • 1940s+: Statistical N-grams (limited 1-3 token local context).
  • 2014: Seq2Seq models (compressing whole sentences into a single "thought vector").
  • 2015: Attention mechanisms (allowing decoder to query all source positions).
  • 2017: The Transformer (Attention Is All You Need — eliminating recurrence).
Slide 3 of 4 · The GPT Mechanism
Autoregressive Generation

GPT models estimate the conditional probability of the next token:

$$P(t_{n+1} \mid t_1, t_2, \ldots, t_n)$$
  • Generative: Produces new text token-by-token.
  • Pre-trained: Learns representations from broad web corpora.
  • Transformer: Multi-head self-attention connects all token positions.
Slide 4 of 4 · Operational Prompts
Vague vs Designed Prompts
  • Vague: "Explain transformers." (Produces generic textbook summary).
  • Designed: Specify target audience, scope, length constraints, and required comparison tables.
  • Three Limits: Not a search engine, finite context window, fluent ≠ verified.
1 / 4

The Architectural Bottleneck

In early sequence-to-sequence translation (2014), an encoder compressed an entire paragraph into a single vector. For longer sentences, crucial entities and grammatical relationships were lost. Attention solved this by allowing the decoder to dynamically weight and consult every source word at each generation step.

1. Not a Search Engine

Produces statistically plausible continuations without inherent fact verification.

2. Finite Context

Selection, compression, and ranking of information are required engineering tasks.

3. Fluency ≠ Accuracy

Grammatical polish does not guarantee logical validity or empirical truth.

Module 02 · ~17 min read

Understanding How Language Models Work

Big Idea: To use a language model well, understand what it actually processes: tokens, probability distributions, and context.

🖥 Interactive Presentation Slides · Module 2
Slide 1 of 3 · Representation
Tokens & Tokenization Realities

Models process token integer IDs, not raw human characters:

  • Common words are 1 token; rare or compound words split into 2-4 subwords.
  • Spelling, anagrams, and letter counts are difficult because individual letters are hidden inside token IDs.
  • Non-English languages often require significantly more tokens for the same meaning.
Slide 2 of 3 · Softmax Math
Softmax & Temperature (T)

The network outputs raw logits ($z_i$), converted to probabilities via:

$$p_i(T) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$
  • Low Temperature (0.1–0.3): Concentrates probability on top candidate (deterministic, factual).
  • High Temperature (0.8–1.2): Flattens distribution, increasing vocabulary diversity and novelty.
Slide 3 of 3 · Hallucinations
The 3 Types of Hallucinations & Defenses
  • Factual: Inventing wrong dates, names, or events.
  • Logical: Generating conclusions that contradict supplied prompt data.
  • Structural: Inventing fake DOIs, academic citations, or nonexistent API endpoints.
  • Defenses: Provide source grounding, negative fallback ("Say I don't know"), and tool lookups.

Self-Attention & Causal Masking

In causal transformers, tokens cannot attend to future positions. A lower-triangular causal mask enforces strictly left-to-right generation, meaning position 2 can attend only to positions 1 and 2, but never 3.

Chat Models, Human Feedback, and Tools

Big Idea: A base model completes text. A chat assistant is aligned to participate in structured conversation, follow boundaries, and operate tools.

🖥 Interactive Presentation Slides · Module 3
Slide 1 of 2 · Alignment
The Training Pipeline: SFT to RLHF
  • Pre-training: Base model trained on internet tokens.
  • SFT: Supervised fine-tuning teaches assistant persona.
  • Reward Model: Trained on human preference rankings.
  • RLHF (PPO): Optimizes policy against reward model. Beware reward hacking!
Slide 2 of 2 · Tool Calling
How Tool Calling Actually Works
  • Model never touches external databases directly; it emits structured JSON function arguments.
  • The application software executes the real API call and returns the response as a tool message.
  • Read-only tools (search, check status) have low risk; write-capable tools require user confirmation.

Designing Applications with Language Models

Big Idea: The model produces text; the application turns a real-world problem into model input and turns generated text into verified results.

🖥 Interactive Presentation Slides · Module 4
Slide 1 of 2 · System Loops
The 4-Stage Feedforward Pipeline
  • 1. Retrieval: Fetch relevant knowledge base articles & user context.
  • 2. Snippetizing: Chunk large documents into focused passages.
  • 3. Prioritization: Score and rank snippets by recency and relevance.
  • 4. Assembly: Build the operational prompt within context budget.
Slide 2 of 2 · Verification
Evaluation: Offline vs Online
  • Offline Testing: Run against 50-500 test cases with ground-truth answers; check JSON schema validity and test code execution.
  • Online Telemetry: Track user acceptance rates, downstream revisions, and task completion instead of relying on subjective feedback.

The Little Red Riding Hood Principle

Prompts should use familiar structural formats (dialogues, standard reports, structured schemas). When the input pattern is clear and recognizable, the expected continuation is much easier for the model to infer accurately.

Module 05 · ~22 min read

Prompt Content, Context, and RAG

Big Idea: The quality of response depends on which information enters the prompt. The core engineering challenge is to find, prioritize, and present the most useful context.

🖥 Interactive Presentation Slides · Module 5
Slide 1 of 2 · Retrieval Math
Lexical vs Neural Embeddings
  • Lexical (Jaccard / BM25): $J(A, B) = \frac{|A \cap B|}{|A \cup B|}$. Best for exact error codes, part numbers, and verbatim matching.
  • Neural (Cosine Similarity): $\operatorname{cosim}(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \|\mathbf{b}\|}$. Best for synonyms, paraphrasing, and multilingual queries.
Slide 2 of 2 · Architecture
The Two RAG Pipelines
  • Offline Indexing: Collect documents → Split into chunks (sliding window) → Embed chunks → Store in vector index. (Generative LLM is not used here!).
  • Request-Time: Embed query → Retrieve top-$k$ nearest chunks → Assemble prompt → Generative LLM creates grounded answer.

SLIDING WINDOW CHUNKING IN PYTHON
def snippetize(text: str, window_words: int = 200, stride_words: int = 120) -> list[str]:
    words = text.split()
    chunks = []
    for start in range(0, len(words), stride_words):
        chunk = words[start:start + window_words]
        if not chunk: break
        chunks.append(" ".join(chunk))
        if start + window_words >= len(words): break
    return chunks

Your Mission: Treat prompts as reproducible experimental designs: make a hypothesis, test alternatives, record evidence, and document what changed.

Lab 1: Interactive Fallacy Case Explorer

Click any case to inspect the argument and reveal the expert ground-truth analysis:

Case A

“Sales started falling after we introduced a new logo. This proves that the logo change discouraged customers.”

False Cause (Post hoc): Temporal order alone does not prove causation; market trends, seasonality, or competitor actions were ignored.
Case B

“This supplement must work because a famous actor said in an interview that it made them feel great.”

Appeal to Authority: Celebrity endorsement does not constitute clinical or pharmacological evidence.
Case C

“I met two rude waiters at this restaurant chain. Clearly, the entire company has terrible staff.”

Hasty Generalization: A sample of two cannot generalize across hundreds of employees.
Case D

“If we allow students to use phones in class, within a year nobody will pay attention and education will collapse.”

Slippery Slope: Asserts an extreme catastrophic chain without justifying the necessity of each step.
Case H

“A study involving 10,000 people indicates that exercise reduces heart disease. Therefore, programs encouraging exercise are worthwhile.”

No Clear Fallacy (Sound Practical Argument): Cites substantial empirical evidence supporting a proportionate recommendation.

Final Lesson: Prompt engineering becomes a science when you can explain what you changed, why you changed it, how you evaluated it, and whether it improved the result.
