01-introduction.md · Module 01

01. Foundations of Prompt Engineering & Transformer Evolution

⏱️ 12 min read · 2 Interactive Labs

Prompt engineering is the empirical science of structuring instructions, contextual evidence, examples, and constraints so that Large Language Models generate reliable, useful continuations. Given the prefix "The most important discovery of the experiment was...", a model could continue with a physics paper, a sci-fi story, or an executive summary—the surrounding prompt architecture determines which distribution wins.

📊 Interactive Lecture Slides — Module 01 1 / 4

Slide 1: The Core Continuation Principle

An LLM is not an oracle or database lookup engine; it is a conditional probability engine P(w_t | w_1 ... w_{t-1}). Every word, delimiter, and formatting cue alters the trajectory of the generated continuation.

Slide 2: Historical Evolution — From RNNs to Transformers (2017)

Classical Seq2Seq RNN/LSTM models compressed entire input sequences into a single fixed-size hidden vector bottleneck. Vaswani et al. (2017) introduced the Transformer ("Attention Is All You Need"), eliminating recurrence in favor of parallel Multi-Head Self-Attention.

Slide 3: What Does GPT Stand For?

Generative (produces new token sequences autoregressively), Pre-trained (learns broad world & linguistic structure from trillions of unlabeled web tokens), Transformer (uses causal self-attention layers to weigh context dynamically).

Slide 4: Zero-Shot, Few-Shot & Chain-of-Thought

Zero-shot relies purely on pre-trained weights. Few-shot (In-Context Learning) supplies 2–5 input/output demonstrations inside the prompt. Chain-of-Thought (CoT) allocates intermediate tokens to reason step-by-step before committing to a final answer.

🎯 5 Pillars of Prompt Anatomy

1. System Persona/Role, 2. Explicit Task Directive, 3. Delimited Contextual Evidence, 4. Negative Constraints & Guardrails, 5. Deterministic Output Schema (JSON / Markdown Table).

🧠 In-Context Learning (Few-Shot)

Without updating neural weights, providing 3–5 structured input→output exemplars locks in edge-case handling, tone, and exact label formatting.

🔗 Chain-of-Thought (CoT)

Forcing the model to generate intermediate reasoning steps ("Let's think step by step") prevents premature token commitment on complex math and logic tasks.

02-understanding-llms.md · Module 02

02. Understanding LLMs: Tokenization, Self-Attention & Sampling

⏱️ 18 min read · 3 Interactive Labs

Large Language Models do not read words or store facts like a relational database. They segment text into sub-word tokens via Byte-Pair Encoding (BPE), compute contextual representations through causal Multi-Head Self-Attention, output raw logits over the vocabulary, and sample the next token using Softmax scaled by Temperature ($T$), Top-$k$, and Top-$p$.

📊 Interactive Lecture Slides — Module 02 1 / 4

Slide 1: Subword Tokenization (BPE) & Token Costs

1 token ≈ 4 characters or 0.75 words in English. Frequent words ("apple") are 1 token, while rare words, code identifiers, or agglutinative languages (Turkish/Polish) split into multiple sub-word tokens—explaining why LLMs struggle with character-level tasks like reversing words or counting letters in "strawberry".

Slide 2: Causal Self-Attention & Query-Key-Value (QKV)

Attention(Q,K,V) = softmax(QK^T / √d_k)V. Causal masking ensures token t can only attend to tokens ≤ t. Multi-head attention tracks syntax, coreference ("it" → "animal"), and semantic dependencies simultaneously.

Slide 3: Softmax, Temperature (T), Top-k & Top-p

P_i = exp(z_i / T) / Σ exp(z_j / T). As T → 0, decoding becomes greedy/deterministic. As T > 1, probabilities flatten. Top-k restricts sampling to the k most likely tokens; Top-p (Nucleus) dynamically keeps the smallest set of tokens whose cumulative probability ≥ p.

Slide 4: Why Hallucinations Happen

Because training optimizes for plausible next-token continuation rather than factual verification, models confidently fabricate citations, URLs, or API parameters when asked about ungrounded facts.

03-chat-models.md · Module 03

03. Chat Models, RLHF Alignment, Roles & Tool Use

⏱️ 16 min read · 2 Interactive Labs

A base model merely continues text (given a question, it might generate 10 more questions!). Transforming a base predictor into a Helpful, Honest, and Harmless (HHH) Chat Assistant requires Supervised Fine-Tuning (SFT), Reward Modeling from human preferences, Reinforcement Learning (RLHF / PPO), structured ChatML message roles (`system`, `user`, `assistant`, `tool`), and external function calling.

📊 Interactive Lecture Slides — Module 03 1 / 4

Slide 1: Base Completion vs. SFT vs. RLHF Chat Assistant

Pre-training processes ~499B+ tokens of raw web text. SFT trains on ~13,000 human-written assistant demonstrations. RLHF trains a Reward Model on ~33,000 human preference rankings and optimizes the policy via PPO—bringing alignment alongside risks like Reward Hacking and Alignment Tax.

Slide 2: Structured Message Roles & ChatML

Conversations are framed with boundary tokens (<|im_start|>system ... <|im_end|>). The System role sets global rules; User sends requests; Assistant replies or proposes tool calls; Tool returns verified API payloads.

Slide 3: Stateless Memory Illusion & Prompt Injection

LLM APIs are completely stateless between HTTP calls; the application must resend conversation history or a compressed state summary on every turn. Role tags help structure instructions but do NOT make an app immune to Prompt Injection from untrusted documents.

Slide 4: Function Calling & Tool Execution

The LLM never executes code or API calls directly! It emits a structured JSON tool proposal (e.g., timetable_lookup(station="Central")). The host application validates permissions, executes the call, and returns the result as a tool message.

04-designing-llm-applications.md · Module 04

04. Designing Production Applications with Language Models

⏱️ 17 min read · 2 Interactive Labs

An LLM application is a closed-loop transformation pipeline bridging the User Domain and the Model Domain: Retrieve → Snippetize → Prioritize → Assemble Prompt → Generate → Validate → Act. Success is measured in the user's domain through both offline benchmarks and online telemetry.

📊 Interactive Lecture Slides — Module 04 1 / 4

Slide 1: The 4 Dimensions of Application Complexity

Applications vary across Medium (text, voice, web UI, APIs), Abstraction (bounded proofreading vs open-ended IT diagnosis), Context (self-contained vs external docs), and State (stateless one-shot vs evolving multi-turn travel plans).

Slide 2: The 4 Requirements of an Effective Prompt

1. Familiar Format (Little Red Riding Hood principle: match recognizable patterns), 2. Enough Relevant Information, 3. Clear Direction, 4. Controlled Stopping Point.

Slide 3: Application Feedforward Pipeline

Before calling the model, the app performs Context Retrieval, Snippetization, Prioritization (fitting the finite token budget), and Prompt Assembly combining Direct context, Indirect context, and Boilerplate framing.

Slide 4: Stateful Loops, Decomposition & ReAct

Complex tasks use task decomposition (verifiable intermediate steps) and ReAct loops (Reason → Call Search/Tool → Observe Result → Repeat) paired with offline & online evaluation.

05-prompts-context-and-rag.md · Module 05

05. Prompts, Context Engineering & RAG Vector Pipelines

⏱️ 20 min read · 2 Interactive Labs

Retrieval-Augmented Generation (RAG) grounds LLMs in external, private, or rapidly changing knowledge without retraining model weights. Long documents are split into overlapping chunks, indexed via Lexical (Jaccard / BM25) or Neural Vector Embeddings (Cosine Similarity), retrieved at query time, and injected into the prompt with explicit grounding rules.

📊 Interactive Lecture Slides — Module 05 1 / 4

Slide 1: Direct, Indirect & Boilerplate Prompt Content

Direct content comes from the user's immediate input. Indirect content is fetched from knowledge bases, history, or APIs. Boilerplate is the reusable template framing roles, delimiters, and output format.

Slide 2: Sliding-Window Chunking & Stride

Splitting a 50-page manual into fixed windows (e.g. 200 words) with a smaller stride (e.g. 80 words → 120 words overlap) prevents answers from being severed across chunk boundaries.

Slide 3: Lexical (Jaccard / BM25) vs. Neural Vector Embeddings

Jaccard J(A,B) = |A ∩ B| / |A ∪ B| and BM25 excel at exact error codes, IDs, and product names. Dense Vector Embeddings map meaning into R^d space so synonyms ("sluggish PC" ↔ "computer running slowly") match via Cosine Similarity.

Slide 4: Hybrid Search, Reranking & Grounded Answering

Production RAG combines lexical + dense retrieval, re-scores top candidates with a Cross-Encoder Reranker, and instructs the LLM to cite chunk IDs and state when evidence is insufficient.
